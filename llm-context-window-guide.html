大模型上下文

Context Window —— 模型一次能「看见」的全部文本，也是它唯一的信息来源。

源自 Transformer · 2017 以 token 计量 输入与输出共享同一窗口
01

它是什么

模型没有硬盘，也没有长期记忆——它只有一张固定大小的桌子。桌上（窗口内）的一切可见，桌外的一切等于不存在。

▲ 窗口内的一切共同竞争空间；下方为窗口大小演进（Transformer → GPT-3 → Claude 2 → 如今）

02

核心机制 —— 一条序列，共享预算

所有内容被切成 token，拼成一条序列。窗口容量 N = 输入 + 输出，回答本身也在消耗这张桌子。

▲ 出自 Transformer 论文的自注意力机制：长度翻倍，计算约 ×4

03

迷失在中间

窗口大 ≠ 用得好。相关信息放在开头或结尾时模型表现最好，埋在中间则显著退化——U 型曲线。

▲ 即使是号称长上下文的模型，也逃不过这条 U 型曲线

04

五条铁律

1
窗口是输入 + 输出的共享预算
让模型写长文，先扣掉输出预留的额度。
2
计量单位是 token，不是字数
中文约 1–2 字一个 token，代码和表格更贵。
3
窗口大 ≠ 用得好
U 型曲线：关键信息放两端，别埋中间。
4
注意力 O(n²)——长上下文又慢又贵
每个 token 都要和所有 token 计算关系。
5
超限时静默截断，最旧的先掉
模型不会提醒你——它只是"忘了"最早的内容。
