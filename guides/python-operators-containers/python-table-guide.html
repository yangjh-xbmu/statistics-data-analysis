列表的每一项是一行，字典的每个键是一列 —— 行列齐了，就是一张数据表。

它是什么 —— 同一份数据的两种写法

左边是 Python 里的写法，右边是你眼睛看到的形态。它们不是「两种数据」，是同一份数据的两种呈现。

▲ 官方教程把这种写法叫「列表可以嵌套」：列表里装字典，正是「一张表」在 Python 里最朴素的表达

02

核心设计 —— 取一列，得走过去

最反直觉的一点：rows["final"] 一定报错。列表只认位置不认名字，想拿一列，唯一办法是每一行都走一遍。

▲ 报错原文是 list indices must be integers or slices, not str —— 记住它，下次一看到就想起「列表不能按名字取」

四步：取出每一行 → 从行里按名字取值 → 累加与计数 → 格式化输出。第 3 次课的 pandas 会把中间两步一次做完。

04

五条铁律

1
一行为一个字典，一列为一个键
列表项 = 行（个案），字典键 = 列（变量）。这个对应关系认下来，后面所有表格操作都不用重学。
2
列表不能按名字取列 —— rows["final"] 一定报错
列表只认整数下标。取一列必须逐行走过去：先拿到每一行的字典，再按名字取格子。
3
每行要有同一套键，缺的用 get() 兜住
真实数据总有缺字段的行。直接 r['final'] 会在第一个缺考的人身上中断；r.get('final') 给你 None，让你自己决定怎么处理。
4
行序就是表序
列表的顺序是数据的一部分。随手 sort() 会把「原始录入顺序」永久丢掉，要保留就先 sorted() 拿一份新的。
5
这就是 DataFrame 的前身
同一份「列表套字典」，pandas 用一行 pd.read_csv 得到，还额外带行列索引、按列取值、分组聚合 —— 但结构认知与这一页完全一致。
