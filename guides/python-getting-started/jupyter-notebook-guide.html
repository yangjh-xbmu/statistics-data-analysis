Notebook 与内核

.ipynb 是一份 JSON 文档，真正执行的是常驻内存的内核

格式是 JSON 内核 = 常驻内存的 REPL 执行顺序 ≠ 文件顺序
01

它是什么

.ipynb 是一份 JSON 文档，顶层是 cells 数组与 metadata，每个 cell 自带类型、源码，code cell 还存着上一次输出。

▲ 文档是容器，cell 是数组里的元素，输出也写进文档

02

核心设计 —— 内核机制

内核是一个常驻内存的 REPL 进程，变量与对象活在它的内存里，关掉内核变量就没了，但文档里的输出还在。

▲ 文档与内核双向通信，内存与文档各存一份状态

03

运行全程 —— 四步执行

编辑 → 发送 → 执行 → 回写：可以乱序执行，但文档只记住结果，不记住顺序的依据。

▲ 四步闭环，输出回到 cell 下方，但顺序不由文档保证

04

五条铁律

1
输出是历史记录，不是可复现的证明
文档里的输出只是某次运行的快照，不代表从头跑一定成立。
2
执行顺序 ≠ 文件顺序
跳过某格也能跑通，是因为内核还留着之前的变量。
3
交付或求助前必须「重启内核 + 全部运行」
这样才能排除乱序执行留下的假结果，验证从头跑也成立。
4
探索用 .ipynb，固化用 .py
要被反复运行、被别的文件引用的脚本，应写成纯 Python 文件。
5
内核死了变量没、输出还在
变量活在内存，重启即清空；输出写在文档，不随内核消失。
