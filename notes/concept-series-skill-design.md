# 系列化学习材料生成 skill · 设计方案

> 需求：在 learn-studio 的 guide 模式（单概念单页溯源手册）基础上，建立一个新的 skill，把**一组相关概念**变成一套**成系列、可导航、互相一致**的学习材料。
> 触发场景举例：`第 1 次课上半场：环境、Notebook、报错怎么读、变量与基本类型` → 4 张单概念手册 + 1 个学习路径页。

---

## 一、先拆概念：四个概念，四页

把一节课塞进一页，违反 guide 模式的第一原则（单概念、一屏一事）。按下列**四条判据**切分：

| 判据 | 说明 |
|---|---|
| 一句话可定义 | 能用一句「它是什么」说清 |
| 有一手来源 | 至少 3 个可点击的官方出处，且不与邻页高度重叠 |
| 有独立自测点 | 能出 6 道题而不与邻页重复 |
| 有独立核心图 | 能画出 1 张结构图/机制图而不与邻页撞车 |

### 切分结果

| # | 概念 | 建议 slug | 一句话定义 | 核心图 |
|---|---|---|---|---|
| 1 | Python 运行环境 | `python-environment` | 解释器、编辑器、包三者是独立程序，各管一段 | 三层栈：编辑器 → 解释器/内核 → site-packages |
| 2 | Notebook 与内核 | `jupyter-notebook` | `.ipynb` 是一份 JSON 文档，跑它的是常驻内存的内核 | 文档（cell 列表）↔ 内核（REPL + 对象表） |
| 3 | 报错与 Traceback | `python-traceback` | 异常是对象，Traceback 从下往上读，最后一行是类型与原因 | Traceback 解剖 + 异常家族树 |
| 4 | 变量与基本类型 | `python-variables` | 变量是「名字指向对象」，四种基本类型决定它能做什么运算 | 名称→对象绑定图 + 类型四分表 |

### 顺序与依赖

```
① 环境 ──▶ ② Notebook ──▶ ③ 报错怎么读 ──▶ ④ 变量与基本类型
   ▲                                            │
   └────────── ④ 需要 ①② 才能真的跑起来 ◀───────┘
```

- ①②是前提（先能跑），③是**工具性知识**（先学会读，后面写变量时立刻用得上），④是**主体知识**。
- ③ 与 ④ 可以互换顺序；③ 必须排在 ④ 之前讲，否则第一次报错就卡住。
- **可选加细**：④ 自己还含 2~3 个子概念（名称绑定 / 四种类型 / 运算符与格式化），若拆开则是 6 页 + 1 hub。

### 为什么现在的 `python-basics-guide.html` 要拆

它是"四个概念的平均分"：01 讲文档与内核（属 ②），02 讲名称绑定（属 ④），03 讲 Traceback（属 ③），04 的铁律里混了 ①②③④ 各一条。**每节都只能给一句 lead + 一张图**，于是 ② 讲不深（没有 nbformat、没有 cell 状态机）、① 几乎没讲（PATH、版本、包）。拆开后每页才有一手来源的密度。

## 二、三个方案 + 一个基线

| | 方案 A · 薄编排器 | 方案 B · 自包含系列工厂 | 方案 C · 数据驱动生成器 | 基线 D · 不上 skill |
|---|---|---|---|---|
| **做法** | 新 skill 只管"系列"层：切分、排序、来源池、调度逐页生成、交叉链接、系列质检、hub 页；**单页细则仍引用 learn-studio 的 guide 工作流** | 把 guide 的 token、六节模板、quiz 引擎全部内联，形成独立的"系列 + 单页"一体 skill | 概念清单写成 `series.yaml`，用脚本渲染骨架（导航、quiz 引擎、token、链接校验）；正文与手写 SVG 仍由 LLM 逐页产出 | 不建 skill：repo 里放一份 playbook + HTML 骨架模板，每次手工按流程跑 |
| **产物** | `~/.workbuddy/skills/guide-series/`（SKILL.md + 契约 + 片段），约 150 行 | 同左，约 400~600 行 | skill + `scripts/render_series.py` + 模板目录 | `notes/concept-series-playbook.md` + `assets/guide-skeleton.html` |
| **优点** | 单一事实源：guide 规则只在 learn-studio 一处，升级自动受益；无重复维护 | 无外部依赖、可移植、可分享给别人 | 一致性由程序保证（链接、答案分布、术语、导航自动化校验）；批量最快；可增量重生成 | 零维护、最灵活 |
| **风险** | 依赖 learn-studio 存在且稳定；fork 上下文能否读到它需实测 | 与 learn-studio 双份维护，规则必然漂移（你今天刚踩的 CSS 作用域、JS 引号两个坑会再犯） | 前期投入最大；脚本只能管骨架，溯源与图仍是逐页人工/LLM | 每次都要重新交代规则，质量靠当场发挥；页数一多必然不一致 |
| **适合** | 你已经在长期用 learn-studio（现状） | 要分发给别人 / 离线使用 | 这个系列会长到 30 页以上 | 只做一次 |

**推荐：A 起步，把 C 的"质检脚本"当可选增强。**
理由：你的核心资产是 guide 模式的规则（你已投入过多次迭代修坑），复制一份到新 skill 就是给自己造第二份真相。系列层缺的东西只有三样——**切分判据、跨页一致性、系列导航**，写清楚这三样，剩下 90% 复用。

## 三、skill 契约（按方案 A）

**名称**：`guide-series`（用户级：`~/.workbuddy/skills/guide-series/`）
> 若按你的四字母命令习惯，可叫 `gser`，命令 `/gser`。

### 输入（三项，缺则问）

1. **概念组**：一节课 / 一节标题 / 一串概念名（可含"上下文里提到过"的隐含概念）
2. **受众与预算**：谁学、总共多长时间、每页期望阅读时长
3. **落地位置**：目录（默认仓库根 + `guides/` 平铺，或 `guides/<系列名>/`）

### 输出（五类）

| 文件 | 内容 |
|---|---|
| `_series/<系列名>.concepts.md` | **切分表**：slug / 一句话定义 / 判据自检 / 依赖与顺序 / 来源候选 / 自测点。**生成任何页面之前必须先产出并让人确认** |
| `<slug>-guide.html` × N | 每页严守 learn-studio guide 六节结构 + 统一 token，页脚带系列导航 |
| `<系列名>-hub.html` | 学习路径页：概念地图 + 顺序 + 每页一句话 + 依赖标注 + 进度勾选 |
| `_series/<系列名>.sources.md` | 来源池：去重后的一手来源登记表（各页从池里取，不重复考证） |
| 系列质检报告 | 逐页 QC + 跨页一致性 QC 的结果，贴在对话里（或落 `CHECKS.md`） |

### 工作流（7 步，含 1 个强制卡点）

```
① 切分        按四条判据拆概念，给每页一句话定义
② 排序        标依赖与可互换项，画概念地图
   ── 卡点 ── 切分表必须让人确认后才进入页级生成（避免生成 5 页后返工）
③ 来源池      逐概念做一手溯源，登记 URL；发现来源重叠 → 回 ① 考虑合并
④ 骨架        hub 页先做（它定义导航与术语表，各页要回链它）
⑤ 逐页生成    每页独立成轮：研究 → 写 → 自验 → 落盘 → 释放上下文
⑥ 交叉链接    注入 prev / next / 上级 hub 回链；术语与用法统一
⑦ 系列质检    QC 清单 + 截图自验 + 链接可达性
```

### 跨页一致性规则（这是"系列"和"一堆散页"的唯一区别）

1. **同一术语同一措辞**：如「内核」，全系列不出现「kernel 服务 / 解释器进程」等混称。
2. **来源池去重**：同一份官方文档在系列里只考证一次，其他页直接引用。
3. **每页必带导航**：页首面包屑（系列名 › 本页）+ 页脚 prev/next + hub 回链。
4. **自测不重复**：六题里跨页撞题的，换角度（同一事实在 ② 考"识别"、在 ④ 考"应用"可以，原题照搬不行）。
5. **答案分布均衡**：整个系列的正确答案索引要打散（单页 1,0,2,3,0,2 这种级别即可，禁止全 C）。
6. **视觉零漂移**：token、quiz 引擎、SVG 字号一律不用重写，从骨架片段复制。

### 上下文经济（决定这套 skill 能不能跑通）

一页手册约 400 行 HTML。四页连做会撑爆上下文，所以：
- **切分表先行**，确认后每页**独立成轮**生成，写完即落盘，不把已完成页的正文留在上下文里；
- 把 header / 导航 / quiz 引擎做成**"复制即用"的骨架片段**，每页只写正文与 SVG；
- hub 页**先于**内容页做，避免后面回头补导航。

### 反模式（写进 SKILL.md 的禁止项）

- 一页塞多个概念（判据不通过就拆）
- 没确认切分表就开始生成页
- 为"系列感"引入第二强调色、icon、卡片阴影（破坏 guide 的视觉纪律）
- 把共享样式改成外链 `assets/style.css`（毁掉单文件便携性——副本优于链接）
- 页与页之间只靠文件名暗示关系，没有可点导航

### 验收标准

1. 每页：`node --check` 通过、答案分布打散、CSS 用容器作用域、每节 ≤ 一句 lead + 一张图；
2. 系列：hub 能点到每一页，每页能回到 hub 与前后页；术语与来源无重复考证；
3. 视觉：截图逐段看过，无文字溢出、无连线穿越图形、无孤立单字行。
