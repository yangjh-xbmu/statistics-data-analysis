LLM Wiki

让大模型把资料「编译」成互链知识库 —— 先消化，再提问。

源自 Karpathy 的知识管理思路 先编译，后提问 Git 版本控制 · 可人工审核 Obsidian 兼容双链
01

它是什么

LLM Wiki 不是「用大模型写维基百科」，而是一套知识管理范式：把原始文档交给大模型，让它提取、归纳、互链成一个结构化的持久知识库。之后的所有提问，都基于这个 Wiki 而不是重新翻原文。

▲ 原始资料不可变；模型只写 wiki/ 层，每读一篇新资料，Wiki 就变厚一点

02

与 RAG 的区别 —— 临时翻书 vs 整理成册

RAG 每次提问都去原始文档里检索碎片，用完即忘；LLM Wiki 先把资料消化整理成结构化百科，之后所有问答都基于它。

▲ 一句话：RAG 是临时翻书，LLM Wiki 是 AI 帮你整理了一本不断更新的内部百科

03

三层结构 —— 不可变层 · 知识层 · 图谱层

整个系统分三层：raw/ 原文永不改动，wiki/ 由模型全权维护，graph/ 从双链自动生成可视化。

▲ 关键约束：模型永远不碰 raw/，人类永远不必写 wiki/

04

工作流 —— 四个动词

日常使用只需记四个触发词：ingest · query · lint · graph，外加一个每会话先跑的 health。

▲ 顺序：health → ingest → query，定期 lint；graph 随时可建

05

五条铁律

1
raw/ 不可变 —— 源文档永不修改
保真：知识层出错可以随时从源头重建。
2
先编译，再提问 —— 问答基于 Wiki 页面
回答带 [[页面]] 内联引用，可回溯到源。
3
矛盾在 ingest 时标记，不等 query 时暴雷
新资料与已有主张冲突，当场写在页面里。
4
双链是骨架，页面互链构成知识图谱
[[wikilinks]] 即图谱的边，Obsidian 可直接打开浏览。
5
纯 Markdown + Git 版本控制，防模型乱改
每次 ingest 都能 diff 审核、都能回滚——比黑盒 RAG 可控。
